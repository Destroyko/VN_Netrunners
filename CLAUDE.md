# CLAUDE.md — правила работы с проектом

Игра: сюжетный симулятор жизни хакера + визуальная новелла (рабочее название VN-netrunners).
Движок: **Godot 4, GDScript**. Один разработчик + ИИ. Код пишет в основном ИИ, разработчик читает и проверяет.

## Перед любой задачей

0. **Новая сессия — начни с `docs/handoff.md`**: где остановились и что делать дальше. В конце сессии обнови его.
1. Определи текущий этап по `docs/roadmap.md`. Делай только задачи текущего этапа.
2. Прочитай документы по теме задачи (карта — в `README.md`). Минимум:
   - архитектура — `docs/tech/architecture.md` (обязательно перед кодом);
   - тесты — `docs/tech/testing.md`;
   - механика — соответствующий файл в `docs/gameplay/`;
   - квесты и данные — `docs/tech/quest-format.md`;
   - новая механика или связь с сюжетом — `docs/tech/gates.md` (песочница и рельсы).
3. Не придумывай механики, которых нет в документах. Если без решения не обойтись — предложи варианты и спроси.
4. Новые идеи, не относящиеся к задаче, — в `ideas/inbox.md`, не в код.
5. **Открытый вопрос или противоречие между документами — в `docs/open-questions.md`**, одной строкой со ссылкой. Не оставляй их только в ответе или в коде; решили — перенеси в «Закрыто» и добавь запись в `docs/decisions.md`.

## Архитектура — коротко (подробно: `docs/tech/architecture.md`)

- **Состояние игры — в одном месте** (`GameState`). Флаги, переменные, деньги, статы, прогресс квестов. Системы не хранят копий состояния у себя.
- **Системы общаются через шину событий** (`EventBus`) и `GameState`. Система не вызывает другую систему напрямую и не лезет в UI.
- **Сюжет и последствия — данными.** Квесты, триггеры, новости, узлы сети, файлы — JSON в `data/`. Условия и эффекты описываются одним общим языком и считаются одним общим модулем (`Conditions` / `Effects`).
- **Логика отдельно от UI.** Правила (терминал, файловая система, головоломки, экономика) — чистые классы GDScript без сцен. UI только показывает состояние и передаёт команды. Так логику можно тестировать без запуска сцен.
- **Случайность только через `Rng` с сидом.** Никаких `randi()` напрямую — иначе нельзя воспроизвести баг и протестировать генераторы.
- **Числа баланса — в `data/balance.json`**, не в коде.
- **Песочница и рельсы разделены** (`docs/tech/gates.md`). Механики (терминал, сеть, головоломки, заметность) не знают сюжета: в `docs/gameplay/`, `docs/tech/` и в `src/` нет персонажей, чекпоинтов и эпизодов. Сюжет лишь открывает **ворота** (`gate.*`, `prog.*`, `pc.*`, `reveal_node`, `skill.*`, `progress.rank`), а связь «чекпоинт → ворота» записана в одном месте — `docs/story/main-arc.md`. Новая механика приходит со своими воротами, значением по умолчанию и способом открыть их руками (консоль F1).

## Структура репозитория

```
project.godot
CLAUDE.md, README.md
docs/            — дизайн-документы (.gdignore — Godot их не импортирует)
ideas/           — входящие идеи (.gdignore)
src/
  autoload/      — синглтоны: GameState, EventBus, Clock, Rng, HeatManager, QuestManager, TriggerManager, NewsManager, SaveManager
                   плюс инфраструктурные (не игровые системы): WindowGuard — пропорции окна
  core/          — общая логика: Conditions, Effects, DataLoader, Validator
  systems/       — игровые системы (чистая логика): terminal, filesystem, network, puzzles, economy, needs, heat
  ui/            — сцены и скрипты интерфейса: desktop, windows, apps
  debug/         — консоль разработчика и отладочные инструменты
data/            — контент в JSON: quests, triggers, nodes, news, programs.json, puzzles/, balance.json
assets/          — графика, шрифты, звук
test/
  unit/          — тесты логики (быстрые)
  integration/   — тесты связок систем и сценариев
tools/           — скрипты: валидатор данных, отчёты по сложности головоломок
```

## Стиль кода

- GDScript со **статической типизацией** (`var x: int`, `func f(a: String) -> bool`).
- Имена в коде — на английском; `snake_case` для переменных и функций, `PascalCase` для классов, `UPPER_CASE` для констант.
- Комментарии — **на русском**, коротко: *почему* так сделано, а не *что* делает строка.
- Один файл — одна ответственность. Это главное правило, а не число строк: делим по смыслу (например, отдельно правила и отдельно разбор команд), а не чтобы уложиться в лимит. Файл за ~500 строк — повод проверить, не слиплись ли две ответственности; если нет, оставляем как есть.
- Сигналы называются в прошедшем времени: `hack_completed`, `file_deleted`, `day_started`.
- Id в данных — `snake_case` с префиксом: `quest_…`, `node_…`, `news_…`, `trigger_…`.
- Флаги — с пространством имён: `story.debt_revealed`, `quest.side_cheating_husband.stage`, `world.police_raid_done`. `story.*`, `quest.*`, `world.*` — рельсы; `gate.*`, `prog.*`, `pc.*`, `deepscan.*` — механики, код песочницы читает только их.

## Тесты

- Фреймворк: **GUT**. Запуск:
  `godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://test -gexit`
- Любая новая логика в `systems/` или `core/` — с unit-тестами.
- Исправляешь баг — сначала тест, который его воспроизводит.
- После изменения данных — запусти валидатор (`tools/`).
- Генераторы головоломок проверяются солвером и отчётом по сложности (`docs/tech/testing.md`).

## Как вести работу

- Маленькие шаги: одна задача — один логичный коммит. Сообщение коммита — на русском, что и зачем.
- Перед коммитом: тесты зелёные, валидатор данных без ошибок.
- Изменил механику или формат данных — обнови соответствующий документ в `docs/` и добавь строку в `docs/decisions.md`.
- После задачи кратко объясни разработчику, что сделано и **как это устроено** (какие файлы, как связаны). Разработчик хочет понимать код, а не только получать его.
- Не добавляй сторонние плагины без согласования.
- Сохранения: формат сейва версионируется. Меняешь структуру `GameState` — добавь миграцию.

## Чего не делать

- Не писать реальные хакерские техники, эксплойты и работающие инструкции. Все взломы в игре вымышленные.
- Не называть в коде и механических доках сюжет (`story.*`, соседка, группа, чекпоинт): нужна новая развилка — заведи ворота.
- Не хардкодить сюжетные проверки в UI или системах (`if quest_x_done: …` в коде окна) — только через триггеры и условия в данных.
- Не обращаться к узлам сцены через длинные пути (`get_node("../../..")`) из логики.
- Не использовать глобальные переменные кроме описанных автозагрузок.
