# Сообщения

Приложение «Сообщения» — в телефоне и на ПК, данные одни (`devices.md`). Чаты с персонажами:
сообщения приходят от них, герой отвечает выбором из готовых вариантов. Свободного текста нет.

## Формат

`data/messages/msg_*.json` — одно сообщение на файл:

```json
{
  "id": "msg_test",
  "from": "roommate",
  "text": "Ты дома? Это {name_roommate}.",
  "replies": [
    {"id": "yes", "text": "Дома.", "effects": [{"send_text": "msg_test_after"}]},
    {"id": "no", "text": "Нет.", "requires": [], "effects": [{"rep": ["roommate", -1]}]}
  ]
}
```

- `from` — персонаж из `data/characters.json`; имя в чате — его `name` (с `{name_*}`).
- `replies` необязательны. У ответа свои `requires` (виден ли вариант) и `effects`.
- Ответ на ответ — эффект `send_text` (сразу) или `schedule` (позже, «напишет вечером»).

## Правила

- Сообщение приходит эффектом `{"send_text": "msg_x"}` — из квеста, триггера, диалога, консоли
  (`effect {"send_text": "msg_x"}`). Одно и то же может прийти не раз.
- Чаты — по собеседникам; последний написавший — сверху. Открыл чат — всё в нём прочитано.
- Ответить можно на последнее сообщение с вариантами, один раз.
- Непрочитанное (сообщения и почта) видно в строке телефона: `● N`.
- Шина: `message_received`, `messages_read`, `message_replied` — квесты и триггеры могут ждать
  ответа так же, как ответа на письмо.
- Переписка — переменная `messages.log` (в сейве).

## Окно на ПК (решено 25.11.2026)

Контакты и чаты, варианты ответа, всплывающее уведомление справа внизу над часами (5–10 секунд,
клик открывает чат), звук, прочитанное синхронно с телефоном — `devices.md`, «Мессенджер на ПК».

Сделано 25.11.2026 (шаг 7 M3): на ПК окно в два столбца (`MessagesApp.set_wide`) — слева чаты с
началом последнего сообщения и числом непрочитанных, справа открытый чат и ответы. Уведомления —
`MessageToasts`: до трёх в стопке, 7 секунд, клик открывает чат, открытый мессенджер их убирает,
пока окно в фокусе — не всплывают. Звук — по сигналу `notification_shown`, плеер — шаг 17.
