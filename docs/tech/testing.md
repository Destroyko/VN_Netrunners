# Тестирование и инструменты

## Фреймворк — GUT

- GUT (Godot Unit Test) — устоявшийся фреймворк для проектов на чистом GDScript. Альтернатива GdUnit4 сильнее в C# — нам не нужно.
- Версия GUT подбирается под версию Godot (ветки по версиям движка). Стоит **9.7.1** (ветка `godot_4_7`) под Godot **4.7.2**.
- Без `.gutconfig.json` в корне GUT не видит подпапки `test/`, поэтому файл есть в репозитории.
- Запуск без окна (headless):
  `godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://test -gexit`
- `test/unit` — быстрые тесты логики; `test/integration` — связки систем и сценарии.
- Позже: автозапуск тестов в GitHub Actions на каждый push.

## Что покрываем тестами

| Что | Как |
| --- | --- |
| Файловая система, терминал, сеть | Unit-тесты: команда → ожидаемое состояние |
| Условия и эффекты | Unit-тесты на каждый тип |
| Квесты и триггеры | Integration: загрузить JSON, отправить события, проверить флаги и эффекты |
| Экономика и баланс | Симуляция N игровых дней с простым «ботом» → отчёт: `godot --headless -s tools/balance_sim.gd -- days=7 seed=1` (логика — `src/systems/economy/balance_sim.gd`, сделано в M2) |
| Генераторы головоломок | Солвер + отчёт по сложности (ниже) |
| Данные | Валидатор всех JSON |

## Головоломки: как генератор «понимает» сложность

Подход из практики процедурной генерации головоломок: **генерировать → решать солвером → измерять → отбирать**. В исследованиях по судоку и логическим головоломкам сложность хорошо оценивается через работу солвера (сколько шагов, ветвлений, «петель» ему нужно), а для Wordle-подобных игр — через то, сколько вариантов остаётся после подсказок и сколько попыток нужно оптимальному решателю.

### Конвейер

1. **Генератор** с сидом: `generate(type, difficulty, seed)` → головоломка. Один сид = всегда одна и та же головоломка (воспроизводимость).
2. **Солвер** для каждого типа — программа, которая решает головоломку перебором или жадной стратегией.
3. **Метрики** из солвера → **оценка сложности** (число).
4. **Отбор:** если оценка не попадает в диапазон нужного уровня — генерируем заново (с новым сидом).
5. **Гарантия решаемости:** головоломка без решения никогда не попадает к игроку.

### Метрики по типам

| Головоломка | Метрики | Что делает сложнее |
| --- | --- | --- |
| **Пароль** (угадать слово по подсказкам) | Сколько слов-кандидатов осталось после стартовых подсказок; среднее число попыток у солвера, выбирающего слово с максимальной информацией (энтропией); редкость слова | Длиннее слово, больше словарь, меньше найденных при разведке букв, меньше попыток |
| **Матрица** (выбор по строкам и столбцам) | Есть ли решение; минимальное число ходов; сколько разных решений; сколько вариантов перебрал солвер; запас ходов (буфер − минимум) | Больше матрица, длиннее последовательности, меньше запас ходов, меньше решений |

### Инструменты

- **Отчёт по сложности** (`tools/puzzle_report`): сгенерировать, например, по 1000 головоломок на каждый уровень сложности → таблица (CSV): распределение метрик, доля отбракованных, время генерации. Запускается без окна.
- **Песочница головоломок** (в debug-меню): выбрать тип, уровень, сид → сыграть; показать метрики и «эталонное» решение.
- **Калибровка по людям:** в прототипе записывать время решения и число ошибок игрока. Метрики солвера лишь коррелируют с ощущением сложности у людей — пороги уровней подстраиваем по реальным данным плейтеста.

## Консоль разработчика (debug)

Доступна только в отладочной сборке:
- изменить деньги, заметность, сытость, энергию, время, день, ранг;
- поставить / снять флаг; выполнить эффект из JSON;
- перейти к этапу квеста; запустить триггер / новость;
- открыть любую головоломку с выбранным сидом и сложностью;
- загрузить **сценарий** — готовое состояние игры из JSON (например, «день 5, долг раскрыт, ранг 2»), чтобы проверять середину игры без прохождения с начала.

## Отчёт об ошибке: журнал сессии и F9

Сделано 15.11.2026: чтобы баг было видно не только по скриншоту, но и по пути к нему.

- **Журнал сессии.** Каждый запуск отладочной сборки пишет `bugreports/sessions/<время>.log` в папке
  проекта: команды терминала и консоли F1, открытие головоломок (вид, ступень, сид, узел, порт),
  ходы в них и итог, все события `EventBus` (кроме ежеминутного `time_advanced`), смену сцен,
  ошибки Godot. В каждой строке — реальное время от запуска и игровое время.
- **Снимок «здесь баг»: F9** (или `bug [заметка]` в консоли F1). Папка `bugreports/<время>/`:
  `screenshot.png`, `state.json` (всё `GameState` + сид + сцена), `session.log` (журнал до этого
  момента), `note.txt` (заметка, если есть). **Последний снимок — последняя папка по имени.**
- **Как чинить по снимку:** взять последнюю папку, по `session.log` и сиду написать тест, который
  повторяет путь и ловит ошибку, потом чинить (правило «сначала тест»). Головоломки по сиду
  воспроизводятся точно; поток дампа зависит только от сида и пойманных кусков.
- Папка `bugreports/` в `.gitignore` и с `.gdignore` (Godot не импортирует скриншоты).
- В тестах (headless) журнал выключен. Код: `src/debug/session_log.gd` (автозагрузка
  `SessionLog`), `bug_report.gd` (имена и формат, тесты), `error_catcher.gd` (ошибки движка).
- **Для публичной альфы** нужен тот же F9 у игроков с отправкой отчёта разработчику — см.
  `open-questions.md`. Сейчас в собранной игре журнал выключен; папка для неё уже предусмотрена
  (`user://bugreports`).
