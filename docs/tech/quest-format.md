# Формат квестов (data-driven)

Квесты описываются **данными, а не кодом**: один JSON-файл = один квест. Игра читает файлы и сама собирает квест. Новый квест = новый файл, без правки кода движка.

## Почему JSON

- Редактируется в любом редакторе, вне Godot.
- Хорошо видно изменения в Git.
- Удобно генерировать и править с помощью ИИ.
- Godot читает JSON штатно.

Альтернатива — ресурсы Godot (`.tres`): удобны в редакторе Godot, но хуже для правки руками и ИИ. Выбор: **JSON**.

## Где лежат файлы (в проекте игры)

```
data/
  quests/
    side/       — второстепенные квесты, один файл на квест
    radiant/    — шаблоны тривиальных квестов
    main/       — сюжетные (позже, тем же форматом)
  nodes/        — компьютеры и устройства мира (ПК мужа, сервер компании…)
  news/         — пул фоновых новостей
```

## Из чего состоит квест

| Блок | Что описывает |
| --- | --- |
| `id`, `title`, `type` | Уникальный id, название, тип (side / radiant / main) |
| `giver` | Кто даёт (персонаж, группа, доска заказов) |
| `channel` | Где квест приходит: `email` (почта), `messenger` (личная переписка), `group_site` (сайт группы) |
| `requires` | Условия появления: флаги, ранг, эпизод, время суток |
| `stages` | Этапы по порядку; у каждого — цели |
| `objectives` | Цели этапа: взломать узел, прочитать / скопировать / удалить файл, поговорить, прийти в локацию, дождаться времени |
| `choices` | Выборы игрока и их условия |
| `effects` | Что меняется: деньги, репутация, заметность, флаги, открыть квест |
| `news` | Новости-последствия с задержкой |
| `deadline_days` | Срок: сколько игровых дней на выполнение с момента получения. Нет поля — квест без срока |
| `outcomes` | Концовки квеста: какой набор эффектов и новостей при каком исходе. У квеста со сроком обязателен исход `expired` |

## Словарь (стандартные типы)

Цели (`objective.type`): `hack_node`, `read_file`, `copy_file`, `delete_file`, `wipe_logs` (почистить логи узла), `mask_backup` (вычистить файл из архивов узла), `talk`, `visit_location`, `wait_until`, `deliver` (отправить файл / сообщение).

Условия (`requires`): `flag`, `not_flag`, `rank_at_least`, `episode_at_least`, `skill_at_least` (`["hacking", 4]`), `has_file` (по `file_id`, где бы он ни лежал на ПК героя), `time_of_day`, `money_at_least`, `heat_at_most`, `day_at_least`, `has_item` (id предмета из `data/items.json`).

Эффекты (`effects`): `money`, `rep` (персонаж / фракция), `heat`, `set_flag`, `set_var`, `clear_flag`, `unlock_quest`, `add_file`, `schedule_news`, `send_message`, `add_note` (запись в блокнот, → [notebook.md](../gameplay/notebook.md)), `reveal_node` (точка входа в сеть, ниже), `give_item` / `take_item` (предмет инвентаря, `data/items.json`), `energy` / `satiety` (прибавить или убавить) и `set_energy` / `set_satiety` (задать) — шкалы героя по ходу сцены (`gameplay/needs.md`). Поле `"admin": true` — логин администратора: на узле сразу с правами (`gameplay/hacking.md`, «Права»).

`reveal_node` — заказ даёт игроку адрес узла и, если клиент его знает, логины. Узел попадает в адресную книгу под своим именем, а перечисленные сервисы открыты заранее (на срок, как у любого вскрытого сервиса):

```json
{ "reveal_node": "node_office_server" }
{ "reveal_node": { "node": "node_husband_pc", "open": ["svc_login"] } }
```

Так же работает в `on_hacked` узла: взломал телефон — получил адрес следующего узла. Валидатор проверяет, что узел и сервисы существуют, а узлы, которые открывает хоть один `reveal_node`, не считает недостижимыми. В `radiant`-квестах вместо id подставляется параметр шаблона (`"{phone}"`).

Новые типы добавляются в код один раз — дальше используются во всех квестах.

## Сроки

Добавлено 13.11.2026. Раньше описать «выполни за три дня» было нечем.

```json
{
  "id": "side_example",
  "deadline_days": 3,
  "outcomes": {
    "done":    { "effects": [{ "money": 300 }] },
    "expired": { "effects": [{ "rep": ["group", -5] }] }
  }
}
```

- Срок считается **с момента получения** квеста, а не от абсолютного дня: так одно и то же
  описание годится и для сюжетного квеста, и для radiant-шаблона.
- Игроку он показывается датой («до пятницы»), а не числом дней — дата понятнее
  и драматичнее (`../gameplay/time.md`).
- Истёк — срабатывает исход `expired` со своими эффектами. Поэтому у квеста со сроком этот
  исход обязателен, иначе провал по времени не имел бы последствий. Валидатор это проверяет.
- Отметка о сроке появляется в приложении «Календарь» сама: оно собирает её из данных квеста.

## Соглашение: файлы проверяются по `file_id`, а не по пути

Решено 13.11.2026. Игрок волен скопировать файл себе, переименовать его и убрать в свою
папку — условие всё равно должно срабатывать. Поэтому и условие `has_file`, и цель `deliver`
(прикрепить файл к заказу) работают по `file_id` из данных узла, а не по пути.

Проверка одна и простая: **лежит ли нужный `file_id` где-нибудь на ПК героя.** Один файл —
один id; архив или бэкап это самостоятельный файл со своим id, а не копия цели
(→ [terminal-spec.md](terminal-spec.md)).

```json
{ "type": "deliver", "what": "file_evidence_hotel", "to": "client_wife" }
```

Так же работает скрытая концовка: она смотрит, сколько файлов-компромата лежит у героя
на ПК, где угодно (→ `../story/mysteries.md`).

## Соглашение: заметание следов — необязательная цель

Решено 13.11.2026. У каждого квеста со взломом есть необязательная цель «почистить логи».
Так игрок узнаёт о росте заметности **из результатов задания**, а не из всплывающих
подсказок во время взлома (см. [heat.md](../gameplay/heat.md)).

```json
{
  "id": "collect",
  "objectives": [{ "type": "hack_node", "node": "node_husband_pc" }],
  "optional": [
    { "type": "wipe_logs", "node": "node_husband_pc",
      "on_done": [{ "money": 40 }, { "rep": ["group", 1] }] }
  ]
}
```

- Выполнил — небольшой бонус: немного денег и репутации. Именно бонус, не основная награда,
  иначе аккуратность станет обязательной и перестанет быть выбором.
- Не выполнил — цель в итогах помечена невыполненной, а заметность уже выросла
  на `heat.gain_logs_left`. Наказание не добавляется: оно и есть сама заметность.
- Размер бонуса — в данных квеста, а не в коде: разные заказчики платят по-разному.

## Шаблон тривиального квеста (radiant)

Те же поля + параметры, которые подставляются случайно, и кулдаун:

```json
{
  "id": "radiant_stolen_phone",
  "type": "radiant",
  "channel": "group_site",
  "cooldown_days": 2,
  "params": { "owner": "random_name", "phone": "random_phone_node", "reward": [80, 150] },
  "stages": [
    { "id": "locate", "objectives": [
      { "type": "hack_node", "node": "{phone}" },
      { "type": "deliver", "what": "geo_location", "to": "{owner}" } ] }
  ],
  "outcomes": { "done": { "effects": [{ "money": "{reward}" }] } }
}
```

## Защита от ошибок

- **Валидатор**: скрипт, который проверяет все JSON-файлы: правильные поля, существующие узлы, файлы, персонажи, новости, нет «висячих» ссылок. Запускается перед каждым билдом.
- Описание формата как JSON Schema — редактор (VS Code) сам подсказывает поля и ошибки.

## Связь с диалогами

Тексты диалогов — в системе диалогов (Dialogic или своя), квест ссылается на них по id. Квест отвечает за логику, диалог — за текст.

## Письма (`data/mail/`)

Добавлено 16.11.2026 (M2, шаг 6). Один файл — одно письмо. Приходит эффектом
`{"send_message": "mail_x"}` — из квеста, триггера или консоли F1 (`effect {...}`).

```json
{
  "id": "mail_test_order",
  "from": "dispatch@example.local",
  "subject": "Проверка почты",
  "body": "Текст письма.",
  "attachments": [
    { "name": "instrukciya.txt", "file_id": "file_test_instruction", "text": "Содержимое" }
  ],
  "replies": [
    { "id": "accept", "text": "Принять", "requires": [], "effects": [{ "set_flag": "world.x" }] },
    { "id": "decline", "text": "Отказаться" }
  ]
}
```

- `id` — с префиксом `mail_`; `from`, `subject`, `body` обязательны.
- **Вложения** сохраняются кнопкой в `/home/mail` на ПК героя (имя занято — `имя_2.txt`); поля
  вложения, кроме `name`, — обычные поля файла (`text`, `size_kb`, `file_id`). По `file_id` их
  находят условия квестов, куда бы игрок их ни переложил.
- **Ответы** — кнопки под письмом. Ответить можно **один раз**; ответ применяет свои `effects`,
  а шина сообщает `mail_replied(uid, mail_id, reply_id)` — так квест узнает о выборе. Ответ с
  `requires` виден, только если условия выполнены (например, герой знает что-то лишнее).
- Одно письмо может прийти несколько раз (шаблоны radiant): у каждого доставленного свой `uid`.
- Валидатор проверяет поля, префикс, вложения, уникальность ответов, их условия и эффекты, а у
  `send_message` в любых данных — что письмо существует.
- Код: `src/systems/mail/mailbox.gd` (`Mailbox`), приложение — `src/ui/desktop/mail_app.gd`,
  ящик в сейве — `GameState.mail_state()` (ключ `mail`; в старом сейве нет — пустой ящик).

## Каналы получения квестов

| Канал | Что приходит |
| --- | --- |
| Почта | Заказы клиентов, официальные письма, часть сюжетных |
| Личные переписки (мессенджер) | Просьбы знакомых, личные квесты персонажей |
| Сайт группы (ПК и смартфон) | Основные хакерские задания, radiant, ранг, репутация |

Формат может ещё поменяться — поэтому в MVP только JSON + валидатор.
