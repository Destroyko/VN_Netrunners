# Архитектура

Главная задача архитектуры — чтобы десятки механик, сюжет и сюжетные триггеры взаимодействовали **без прямой связки друг с другом**. Тогда добавление новой механики или квеста не ломает старые («карточный домик» Darklands).

## Принцип: событие → условие → эффект

Всё взаимодействие в игре сводится к одной схеме:

1. **Событие** — что-то произошло: взломан узел, удалён файл, начался день, головоломка провалена, прочитано письмо.
2. **Условие** — проверка состояния: стоит ли флаг, хватает ли денег, какой ранг, время суток.
3. **Эффект** — изменение: деньги, заметность, флаг, новость, письмо, открыть квест, запустить диалог.

Квесты, сюжетные триггеры, ивенты и новости — это наборы «событие + условие → эффект», описанные в JSON. Код знает только, **как** проверить условие и **как** применить эффект.

## Компоненты (автозагрузки)

| Компонент | Отвечает за | Не делает |
| --- | --- | --- |
| `GameState` | Всё состояние: флаги, переменные, деньги, статы, заметность, прогресс квестов. Единственный источник правды; сериализуется в сейв | Не содержит правил игры |
| `EventBus` | Сигналы-события для всех систем (`hack_completed`, `file_deleted`, `day_started`, `puzzle_failed`…) | Не хранит состояние |
| `Clock` | Игровое время, дни, время суток; продвигает время за действия | Не решает, что происходит в новый день — только сообщает |
| `Rng` | Вся случайность, с сидом | — |
| `QuestManager` | Читает квесты из `data/quests`, ведёт этапы, слушает события, проверяет цели | Не рисует UI |
| `TriggerManager` | Сюжетные и мировые триггеры из `data/triggers`: «при событии X, если условия Y → эффекты Z» | — |
| `NewsManager` | Пул фоновых новостей + запланированные новости-последствия с задержкой | — |
| `SaveManager` | Сохранение / загрузка `GameState`, версии и миграции сейва | — |
| `WindowGuard` | **Инфраструктура, не игровая система.** Держит пропорции окна в рамке при ручном ресайзе (`resolution.md`). Логика — в `src/core/window_aspect.gd` | Не знает об игре |

**Песочница и рельсы.** Системы и их документы не знают сюжета: механика смотрит на нейтральные
ворота (`gate.*`, `prog.*`, `pc.os`), а сюжет — квесты, триггеры, чекпоинты — открывает и закрывает
их эффектами. Реестр ворот и правила — [gates.md](gates.md).

Общие модули (`src/core`):
- `Conditions` — проверяет условие из данных (один язык для квестов, триггеров, диалогов, новостей).
- `Effects` — применяет эффект из данных.
- `DataLoader` — загружает и кэширует JSON.
- `Validator` — проверяет данные (поля, ссылки на id).

## Игровые системы (`src/systems`)

Чистая логика, без сцен. Каждая система:
- читает и меняет только `GameState`;
- сообщает о произошедшем через `EventBus`;
- не знает о других системах и о UI.

| Система | Суть |
| --- | --- |
| `filesystem` | Виртуальная файловая система: свой ПК и узлы, права, системные файлы |
| `network` | Узлы сети, сервисы, защита, подключение, трейс |
| `terminal` | Разбор команд, автодополнение, история; вызывает filesystem / network / программы |
| `puzzles` | Генераторы головоломок, правила, солверы, оценка сложности |
| `heat` | Заметность: рост, спад, пороги |
| `needs` | Сытость, энергия, сон |
| `economy` | Деньги, платежи, аренда, долг |
| `background_tasks` | Долгие задачи (брутфорс) по игровому времени |

## Пример: как всё связывается (квест «Неверный муж»)

1. Игрок в терминале удаляет файл на ПК мужа → `terminal` вызывает `filesystem` → `filesystem` меняет состояние и шлёт `EventBus.file_deleted(node, path)`.
2. `QuestManager` слушает `file_deleted`, видит, что это цель текущего этапа → отмечает цель выполненной.
3. Игрок делает выбор → `QuestManager` применяет эффекты исхода через `Effects`: деньги, репутация, `schedule_news(news_local_murder, delay=1)`.
4. Утром `Clock` шлёт `day_started` → `NewsManager` публикует запланированную новость.
5. `TriggerManager` слушает те же события: например, если `heat > 70` в начале дня — триггер обыска.

Ни одна из систем не знает о квесте. Квест знает только события и эффекты.

## Сюжетные триггеры (`data/triggers`)

Формат — тот же язык условий и эффектов, что у квестов:

```json
{
  "id": "trigger_collectors_step1",
  "on": "day_started",
  "requires": [{ "flag": "story.job_found" }, { "not_flag": "story.collectors_1" }],
  "effects": [{ "send_message": "msg_unknown_call" }, { "set_flag": "story.collectors_1" }],
  "once": true
}
```

Так задаются: лестница намёков коллекторов, подарок флешки, появление посылки, предложение «Сделки» на осмотре, обыск при высокой заметности.

## UI

- Сцены интерфейса подписываются на `EventBus` и читают `GameState`, чтобы обновиться.
- Действия игрока UI передаёт в системы (команда терминала, клик по файлу).
- Окна рабочего стола независимы: закрыть / открыть окно не меняет логику.

## Сохранения

- Сейв = сериализованный `GameState` + номер версии формата.
- Меняется структура → миграция со старой версии.
- Всё, что нельзя восстановить из данных, должно быть в `GameState` (иначе после загрузки мир «забудет» последствия).
