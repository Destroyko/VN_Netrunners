# Диалоги: формат и как они работают

Диалог — **данные, как квест**: один JSON-файл в `data/dialogues/` на одну сцену разговора.
Условия и эффекты — тот же общий язык (`quest-format.md`), поэтому диалог может проверить флаг,
дать деньги, открыть квест или узел, а квест — дождаться, что разговор состоялся.

## Персонажи — один раз, отдельно

`data/characters.json` — кто говорит, как подписан и откуда спрайты:

```json
{
  "roommate": { "name": "{name_roommate}", "portrait": "roommate", "color": "#c98a6b" },
  "landlord": { "name": "{name_landlord}", "portrait": "landlord", "color": "#8a9bb0" },
  "hero":     { "name": "{name_hero}",     "portrait": "",         "color": "#d0d4dc" }
}
```

- **Имена ещё не выбраны** — в тексте стоят подстановки `{name_roommate}`, а сами имена лежат в
  одном месте (`data/names.json`). Выберете имя — поменяется везде, тексты трогать не надо.
- Спрайт — `assets/portraits/chr_<portrait>_<наряд>_<эмоция>.png`: рендер по пояс на прозрачном фоне
  (`art/characters-in-scenes.md`). Наряд берётся из расписания персонажа. Нет картинки — цветная
  плашка с именем: так код работает до арта.
- **Спрайт героя будет** (разработчик, 17.11.2026) — пока заглушка-плашка, как у всех без арта.

## Диалог

```json
{
  "id": "dlg_roommate_meet",
  "start": "hello",
  "nodes": {
    "hello": { "speaker": "roommate", "emotion": "smile",
               "text": "О, ты новый жилец? Я {name_roommate}.", "next": "ask" },
    "ask":   { "speaker": "roommate", "emotion": "neutral",
               "text": "Надолго к нам?",
               "choices": [
                 { "text": "Как получится.",              "next": "calm" },
                 { "text": "Пока не найду, где мама.",   "next": "mom",
                   "requires": [{ "flag": "story.mom_missing" }] },
                 { "text": "Промолчать.",                 "next": "end_cold",
                   "effects": [{ "rep": ["roommate", -1] }] }
               ] },
    "calm":  { "speaker": "roommate", "emotion": "smile", "text": "Ладно. Кухня общая.",
               "effects": [{ "set_flag": "story.met_roommate" }], "end": true },
    "mom":   { "speaker": "roommate", "emotion": "sad", "text": "…Сочувствую.", "next": "calm" },
    "end_cold": { "speaker": "hero", "thought": true, "text": "Не до разговоров.", "end": true }
  }
}
```

**Узел** — одна реплика или развилка:

| Поле | Что значит |
| --- | --- |
| `speaker` | Кто говорит (id из `characters.json`); нет поля — **текст автора** (без имени и портрета: «Ты еле добрался до кровати и уснул») |
| `emotion` | Эмоция портрета: `neutral`, `smile`, `surprise`, `anger`, `sad`, `embarrassed`, `thoughtful` (набор из `style-guide.md`) |
| `text` | Текст реплики; подстановки `{name_*}` |
| `thought` | `true` — мысль героя, а не речь (другой вид в окне) |
| `next` | Следующий узел — продолжение по клику / пробелу |
| `choices` | Выборы игрока: `text`, `next`, `requires` (виден, только если выполнено), `effects` |
| `branch` | Развилка без игрока: `[{ "requires": [...], "next": "x" }, …, { "next": "иначе" }]` — первое подходящее |
| `effects` | Эффекты при показе узла (деньги, флаги, `unlock_quest`, `reveal_node`, `give_item`…) |
| `end` | Диалог закончен |

У узла должно быть ровно одно из `next`, `choices`, `branch`, `end` — валидатор проверит, а
ещё что все `next` ведут в существующие узлы, `start` есть, нет недостижимых узлов, а условия и
эффекты знакомые.

## Как запускается и что делает с игрой

- **Запуск** — эффектом `{"start_dialogue": "dlg_roommate_meet"}`: из триггера, квеста, клика
  по объекту в сцене или по персонажу. Один диалог за раз; новый, пока идёт старый, ждёт в
  очереди.
- **Время стоит**, пока идёт диалог (`Clock.pause("dialog")`, `gameplay/time.md`). Диалог может
  сам перемотать время эффектом (например, «проговорили час»).
- **Квесты**: цель `talk` (`{"type": "talk", "dialogue": "dlg_x"}`) закрывается, когда диалог
  закончился (сигнал `dialogue_ended`). Можно и «закончился в узле N» — если важно, чем кончился.
- **Журнал (`H`)** — все показанные реплики и выбранные ответы, с датой; хранится в
  `GameState` (сейв помнит), последние ~300 строк.
- **Мысли вслух** (`hero_thought`) остаются отдельно — короткая строка внизу экрана без
  остановки времени. Диалог — когда нужна сцена.

## Взаимодействие с персонажами (решено разработчиком 26.11.2026)

Два способа, как начинается разговор:

1. **Сам** — игрок пришёл в нужную локацию, или наступило нужное время, а он уже там (звонки и
   СМС — так же). Это триггер двигателя сюжета (`story-engine.md`): `on` — `location_entered` или
   ход часов, `requires` — где, когда, какой флаг (`at_location`, `weekday`, `time_between`),
   эффект — `start_dialogue`, звонок или `send_message`; `once` или флаг, чтобы не повторялся.
2. **По клику на персонажа** (на спрайт) — обычный путь для разговора лично. Открывается меню
   **тем**: что можно обсудить с этим персонажем сейчас.

**Темы персонажа** (делать сразу после шаблонов квестов, 26.11.2026). У персонажа в данных —
список тем: тема = диалог + условия, когда она видна (флаг квеста, время, отношения), +
`once` (одноразовая). Клик показывает только доступные сейчас; квест открывает нужную тему
флагом («поговорить с Джейн о совместной пробежке»), цель `talk` закрывается, когда диалог темы
кончился. Разные варианты взаимодействий (поговорить, отдать предмет…) — тоже темы. Это подход
storylets: игрок выбирает из того, что сейчас доступно.

## Термины с подсказкой

Названия программ, имена, важные слова в тексте выделяются и **показывают короткую подсказку при
наведении** (разработчик, 17.11.2026): упомянули `passhound` — навёл мышь и понял, о чём речь.

```
"text": "Запусти [[passhound]] на двадцать второй порт."
"text": "Поговори с [[name_roommate|соседкой]]."
```

- `[[id]]` — термин из глоссария `data/glossary.json`: `{ "passhound": { "title": "passhound",
  "hint": "Перехват хэша пароля из дампа памяти сервиса." } }`; в тексте — `title` цветом.
- `[[id|текст]]` — свой текст, подсказка та же.
- Валидатор проверяет, что каждый термин есть в глоссарии. Глоссарий потом пригодится и в
  почте, новостях, заметках.

## Окно на экране

Снизу — панель с текстом: над ним имя цветом персонажа; выборы — кнопками. Спрайт по пояс стоит
над панелью, фон — размытый кадр локации без персонажа (`art/characters-in-scenes.md`). Без спрайта
(автор, мысль) — панель без спрайта, мысль — курсивом и серым.

- **Текст набирается постепенно.** Клик мышью, пробел или Enter **во время набора** — вся строка
  сразу; **после** — следующая реплика.
- **Скорость текста — в настройках**: медленно, обычно, быстро, сразу целиком.
- **Пропуска прочитанного нет** — проще прокликать (разработчик). **Выборов с таймером нет.**

## Как это устроено (M3, шаг 2 — сделано 17.11.2026)

| Что | Где |
| --- | --- |
| Разметка: имена `{name_*}`, термины `[[id]]` → цветные ссылки, текст без разметки для журнала | `src/systems/dialogue/dialogue_text.gd` (`DialogueText`) |
| Ход одного диалога: узлы, выборы с условиями, развилки, эффекты, журнал | `src/systems/dialogue/dialogue_run.gd` (`DialogueRun`) |
| Идущий диалог и очередь, пауза времени, сигналы | автозагрузка `DialogueManager` |
| Окно поверх любой сцены, набор текста, подсказки терминов, журнал по `H` | автозагрузка `DialogueOverlay` (`src/ui/dialogue/`) |
| Проверка данных | `src/core/dialogue_validator.gd` + общий `Validator` (условия, эффекты, `start_dialogue`) |
| Персонажи, имена, глоссарий | `data/characters.json`, `data/names.json`, `data/glossary.json` |
| Скорость текста | `AppSettings.text_speed`, экран настроек |

- Запуск — эффект `{"start_dialogue": "dlg_x"}` или консоль F1 `dialogue dlg_x`. Пробный диалог —
  `data/dialogues/dlg_test.json`.
- Сигналы шины: `dialogue_started`, `dialogue_node_changed`, `dialogue_ended`; цель квеста
  `{"type": "talk", "dialogue": "dlg_x"}` закрывается на `dialogue_ended`.
- Журнал — переменная `dialogue.journal` (последние 300 строк, в сейве); выборы игрока
  отмечены стрелкой.
- Пока диалог на экране, прозрачная подложка не даёт кликать по сцене под ним; клик по ней —
  то же, что пробел. `H` не срабатывает, пока курсор в поле ввода.
- Спрайт — `assets/portraits/chr_<персонаж>_<наряд>_<эмоция>.png`; файла нет — плашка.

## Ввод текста (план, решено 26.11.2026)

Разработчик: стандарт визуальных новелл — игрок вводит текст в диалоге. Нужен узел диалога с полем
ввода, значение сохраняется в переменную состояния и дальше подставляется в тексты, как имена
(`{name_*}`). Первые случаи: имя героя во вступлении и его ник при вступлении в группу (можно и
выбрать из готового списка). Формат узла, ограничения (длина, символы) и где хранится имя, чтобы
`{name_hero}` его видел, — при реализации.

## Звонок (план, решено 26.11.2026)

Разработчик: звонок — обычный диалог, но графически герой как будто держит телефон у уха: телефон
торчит с правого края экрана поверх фона и спрайтов. Телефон виден **только пока открыто окно
диалога**. Картинка телефона — отдельный ассет (`../art/style-guide.md`). Как диалог помечается
звонком в данных — при реализации (П: поле у диалога).

## Катсцена слайдами (план, M3, шаг 15)

Вступление игры — диалог, у которого за текстом не сцена, а картинка во весь экран
(решено 24.11.2026). Предложение формата: поле `image` у узла — путь к рендеру; картинка
держится, пока следующий узел не сменит её; диалог без `image` идёт поверх текущей сцены, как
сейчас. Детали — при реализации шага 15.
