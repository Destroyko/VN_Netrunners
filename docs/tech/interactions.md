# Карта взаимодействий песочницы

Зачем: каждая механика по отдельности работает и покрыта тестами, а дыры прячутся **на стыке
двух систем** — как полоска программы, которая была просто анимацией, хотя итог уже был получен
(25.11.2026). Этот файл держит в одном месте, что каждая механика хранит, как она связана со
временем, какие правила обязаны выполняться всегда и где механики пересекаются. Новая механика
приходит сюда со своими строками (правило — в `CLAUDE.md`), и сразу видно, с чем она пересечётся.

Найденное, но не решённое — в `docs/issues.md` (список issues игры, отдельно от открытых
вопросов дизайна в `open-questions.md`).

## Как пользоваться

Добавляешь или меняешь механику:

1. **Реестр состояния** — что она хранит в `GameState`, кто пишет, кто читает.
2. **Реестр времени** — тратит ли она игровое время и как (сразу, под полоской, промоткой);
   реагирует ли на ход часов или смену дня.
3. **Состояние вне сейва** — что живёт только в памяти (переживёт ли сохранение и загрузку).
4. **Инварианты** — каким из правил ниже она должна подчиняться; новое правило — дописать.
5. **Матрица** — строки для пересечений с механиками, которые она трогает.
6. Сомнительный стык — проверить тестом; не решён — в `docs/issues.md`.

## 2. Реестр времени

Время — главный источник дыр: почти все пересечения идут через него.

### Кто тратит время

| Источник | Как | Сколько |
| --- | --- | --- |
| Ход часов в игре | `Clock.tick` → `advance(1)` | 1 игровая минута = 4 реальные секунды |
| Команды терминала короче 2 минут (`cat`, `ls`…) | `Terminal.spend` → сразу | `action_minutes` |
| Программы и передача файлов (от 2 минут) | `Terminal.spend_then` → `Clock.fast_forward`, итог в конце полоски, `Ctrl+C` | `action_minutes`, размер файлов |
| `probe` (2 минуты) | `Terminal.spend` → `Clock.fast_forward`: полоска без программы, ответ сразу (ISS-016) | `action_minutes.probe` |
| Фоновый подбор пароля | `BackgroundTasks` по `time_advanced`, срок — абсолютная минута | `background.decrypt_minutes` |
| Сон и ожидание (кровать) | `Rest.pass_time` → `advance(1)` подряд, прерывается событиями | до будильника |
| Вырубание | `NeedsManager.sleep_after_pass_out` → `Rest` | до полной энергии |
| Еда | `Shop.apply_food` → `advance` | `eat_minutes` |
| Питание ПК | `PcPower` → `advance` | выключение 1, загрузка 2 |
| Консоль F1 | `time`, `bed` | — |

### Кто живёт по времени

| Слушатель | На что | Что делает |
| --- | --- | --- |
| `HackManager` | `time_advanced` | трейс узла, прайм-тайм, обрыв сеанса |
| `NeedsManager` | `time_advanced` | энергия, сытость, вырубание |
| `HeatManager` | `time_advanced` | спад заметности за тихие сутки |
| `BackgroundManager` | `time_advanced` | фоновый подбор пароля |
| `EconomyManager` | `time_advanced`, `day_started` | доставка, аренда, пеня |
| `QuestManager` | `time_advanced` (раз в час), `day_started` | цели «дождаться», сроки |
| `TriggerManager` | `time_advanced` | `schedule` (отложенные эффекты) |
| `NewsManager` | `day_started` | лента |
| `SaveManager` | `day_started` | автосейв в конце кадра |

### Паузы

Время стоит: диалог (`dialog`), меню игры (`menu`), занавес вырубания (`pass_out`). Ускоренный
отрезок программы на паузе тоже стоит.

## 3. Состояние вне сейва

Живёт только в памяти: при загрузке пропадает, при смене сцены может потеряться.

| Что | Где | Что будет при загрузке / смене сцены |
| --- | --- | --- |
| Идущая программа (`_job`) | `Terminal` | пропадает; итога нет (тест, ISS-003). Новый терминал о прежнем `_job` не знает (ISS-001) |
| Ускоренный отрезок (`_fast_left`) | `Clock` | `Clock.stop()` в главном меню сбрасывает; `PcPower` и `Desktop.discard_kept` — нет (ISS-001) |
| Вопрос y/n (`_pending`) | `Terminal` | общий для консоли, «Файлов» и трансляции; помнит строку без `_local` (ISS-004, ISS-007) |
| Штраф анализа действий (`_ids_extra`) | `Terminal` | пропадает; списывается при следующем `spend` |
| Головоломка, ввод пароля | `Terminal` (`_puzzle`, `_login`) | пропадает, сеанс сброшен; попытка не засчитана — при загрузке по замыслу (та же партия), при обрыве — ISS-009 |
| Идущий диалог и очередь | `DialogueManager` | пропадает |
| Спрятанный стол | `Desktop._kept` (static) | уничтожается при новой игре и выходе в меню |
| Буфер обмена проводника | `FileBrowser.clipboard` (static) | живёт всю сессию игры |
| Уведомления | `MessageToasts` | пропадают со столом |
| Занятые файлы (`Filesystem.locked`) | считает `Terminal.busy_paths` при каждой команде | в сейв не идут: выводятся из `bg.tasks` (и открытого «Блокнота») |

## 4. Инварианты

Правила, которые должны выполняться всегда. Статус: **тест** — есть проверка; **код** — держится
устройством кода, теста нет; **проверить** — сомнения, см. `issues.md`.

| № | Правило | Статус |
| --- | --- | --- |
| И-1 | Итог действия появляется не раньше, чем потрачено его время (программы, передача файлов) | тест (`test_terminal_rights`, «итог в конце полоски»); `probe` — ISS-016 |
| И-2 | Действие на чужом узле требует живого соединения в момент применения итога | тест (rootstep, cp) |
| И-3 | У игрока всегда есть путь к рабочей ОС (флешка-резерв не теряется и не расходуется) | код (`Room.use_item`, квестовая вещь не выбрасывается) |
| И-4 | Квестовый предмет нельзя потерять, пока квест идёт (выброс, полный инвентарь) | тест (`test_inventory`) |
| И-5 | Деньги не уходят в минус | код (`Economy.spend`) |
| И-6 | Сейв в любой момент загружается в согласованное состояние; живое состояние (раздел 3) при загрузке сбрасывается, а не висит | тест (`test_program_jobs`, автосейв посреди передачи) |
| И-7 | Действие мышью и командой проходит одни правила (права, логи, трейс) | код (проводник и «Файлы» вызывают команды терминала) |
| И-8 | Команда «на своём ПК» (`execute_local`) не трогает чужой узел | тест (`test_files_window_stays_on_own_pc_during_session`); нарушается ответом в консоли — ISS-007 |
| И-9 | Потолок заметности за один взлом предсказуем (сейчас 11) | тест (`test_logbook`) |
| И-10 | Время сдвигается только через `Clock`; все, кто живёт по времени, видят каждую минуту | код |
| И-11 | Выключение ПК обрывает всё, что на нём идёт (соединение, фоновые задачи, программы) | нарушается: ISS-001 (тест) |
| И-12 | Пока герой без сознания или спит, действий за ПК не происходит | проверить (ISS-002) |
| И-13 | Спрятанное воротами не видно игроку нигде (значки, ярлыки, меню, списки) | тест (ярлыки, значки) |
| И-14 | Цель квеста «по состоянию» перепроверяется при любом событии, которое может её выполнить | нарушается: `mv` / `cp` на своём ПК — ISS-017 (тест) |
| И-15 | Одновременно идёт одна программа; команда посреди неё (мышью, из окна) не отменяет её итог | тест (`test_second_program_does_not_drop_the_first_result`) |
| И-16 | Ответ на вопрос y/n выполняется там, где задан вопрос (узел, окно); действие в другом окне вопрос не закрывает | нарушается: ISS-004, ISS-007 (тесты) |
| И-17 | Каждая открытая попытка головоломки кончается итогом: выход из окна, провал и обрыв сеанса считаются одинаково | нарушается: ISS-009 (тест) |
| И-18 | Эффекты исхода квеста и `on_done` цели применяются ровно один раз; вложенное событие не меняет этап под внешней обработкой | нарушается: ISS-010, ISS-011 (тесты) |
| И-19 | У каждой доставленной записи (письмо, сообщение) свой `uid` на всю игру | нарушается: ISS-012 (тест) |
| И-20 | Правка, открытая на узле, сохраняется на этот узел, пока он доступен, — что бы ни открыл терминал за это время | нарушается: ISS-008 (тест) |
| И-21 | Сохранить можно, только когда нет полоски; всё, что идёт дольше полоски, — фоновая задача с состоянием в сейве (переживает сейв, загрузку и сон) | решено, чинить (ISS-003) |
