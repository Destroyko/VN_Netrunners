## Что за игра (одним абзацем)

Сюжетная одиночная игра для ПК: симулятор жизни хакера + визуальная новелла. Герой после 8 лет комы живёт в городе, зарабатывает подработками и взломами через ПК и смартфон, следит за сном, едой и деньгами; действия имеют скрытые последствия. Взлом — в духе Hacknet, но казуальнее: терминал с автодополнением, свобода с файлами, короткие головоломки вместо ожидания. Эпизодический выпуск, старт на itch.io. Подробно — `docs/00_overview.md`.

Команды:

```bash
godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://test -gexit   # тесты
godot --headless -s tools/validate_data.gd                           # данные
godot                                                                # игра
```

Если `godot` не находится: winget без прав админа не создаёт алиас, поэтому рядом с exe
лежит обёртка `godot.cmd` в `%LOCALAPPDATA%\Microsoft\WinGet\Packages\GodotEngine.GodotEngine_*\`
(эта папка уже в PATH). В уже открытых терминалах PATH старый — нужен новый терминал.

## Гейт M0 — что ждёт разработчика

Спецификации для M1 написаны, **нужна проверка**. В конце каждой — список вопросов «что подтвердить»:

1. `docs/tech/terminal-spec.md` — команды MVP, автодополнение, формат узла в JSON.
2. `docs/tech/puzzles-spec.md` — правила «пароля» и «матрицы», параметры по сложностям, метрики солвера.
3. `docs/tech/desktop-layout.md` — раскладка рабочего стола и окна терминала.
4. `data/nodes/` — ПК героя + 3 тестовых взлома нарастающей сложности (учебный → обычный с трейсом → два слоя защиты).

Главные вопросы, где нужно решение разработчика:

- **Реального таймера в головоломках нет** (давление даёт трейс в игровых минутах) — это заметно меняет ощущение от игры.
- **Словарь «пароля» — русские слова** или латиница.
- **Частичный успех в «матрице»** или строго «собрал всё / провал».
- **Названия программ:** `passhound`, `gridrunner`, `rootstep`, `logwipe`, `deepscan`.
- **Числа в `balance.json` — заглушки.** Нужны настоящие: длина дня, стоимость действий, стартовые деньги, аренда, расход сытости и энергии, рост и спад заметности.
- **Статусы документов.** Договорились: перед M1 пройти по документам со статусом «обсуждается» и перевести в «утверждено» то, что решено.

## Следующие задачи — M1 «Прототип взлома» (после гейта)

Порядок такой, чтобы каждый шаг можно было проверить тестами:

1. **Файловая система** (`src/systems/filesystem/`): плоский список путей из JSON → дерево, `ls`/`cd`/`cat`/`cp`/`mv`/`rm`, права, системные файлы, маска `*`. Unit-тесты на каждую операцию.
2. **Сеть** (`src/systems/network/`): узлы из `data/nodes`, `scan`/`probe`/`connect`/`dc`, вскрытые сервисы, трейс в игровых минутах.
3. **Терминал** (`src/systems/terminal/`): разбор строки, таблица команд, ошибки по спецификации, история, автодополнение (по ОС).
4. **Головоломки** (`src/systems/puzzles/`): генератор + солвер + метрики для «пароля» и «матрицы», отбор по сложности, `tools/puzzle_report`.
5. **Заметность** (`src/systems/heat/`): рост от провалов и неудалённых логов, спад по дням, порог обыска.
6. **Интерфейс**: рабочий стол, окна, окно терминала с панелями, модальное окно головоломки, заглушки остальных приложений.
7. **Гейт M1:** пройти 3 тестовых взлома и ответить на вопрос — **интересно ли взламывать?**

Правило из `docs/roadmap.md`: работаем только над задачами текущего этапа, новые идеи — в `ideas/inbox.md`.

- Два пути финала.
- Модель генерации графики и точный размер пикселя — решаем на M3.
- Экспорт (M4): Godot не кладёт `.json` в сборку без фильтра `*.json` в настройках экспорта — не забыть.
