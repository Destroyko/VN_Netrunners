## Как работать

**Команды:**

```bash
godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://test -gexit   # тесты
godot --headless -s tools/validate_data.gd                           # валидатор данных
godot                                                                # игра
```

На Windows, если `godot` не находится: winget без прав админа не создаёт алиас, рядом с exe лежит
обёртка `godot.cmd` в `%LOCALAPPDATA%\Microsoft\WinGet\Packages\GodotEngine.GodotEngine_*\`; нужен
новый терминал. Облачная сессия без Godot тесты и валидатор не запускает — скажи об этом
разработчику.

- **Баг** — разработчик жмёт F9 в игре; бери последнюю папку в `bugreports/` (`tech/testing.md`).
- **Консоль разработчика** — F1: открыть ворота, выдать предмет, промотать время.
- **Ветки:** сюжет и графика ведутся в своих ветках и сливаются в `main` поэтапно — чтобы другие
  сессии видели записанное.
- GUT **молча пропускает** тест-скрипт, который не парсится: если тестов стало меньше — ищи
  `GUT WARNING`.

**Разработчик:** Enteii, общается на русском. Бывший веб-разработчик, Python — на уровне скриптов.
Код пишет в основном ИИ; разработчик хочет **понимать** код — объясняй, как устроено сделанное.

- Отвечай коротко и по делу; предлагай варианты с рекомендацией, когда решение за ним.
- Решения — сразу в `decisions.md`; открытые вопросы — в `open-questions.md`; идеи вне задачи — в
  `ideas/inbox.md`, не в код. Чиним сразу только помехи текущей задаче.
